# 楽天商品登録自動化システム 仕様書（初版）

## 1. 文書の目的

現在、Googleスプレッドシートで管理している商品マスターをもとに、楽天市場（RMS）へ新規商品ページを登録する作業を効率化する。

特に、機種・カラー・追加オプション・セット内容などの組み合わせによってSKU数が増え、最大400SKU程度になる商品について、手作業によるコピー＆ペーストを可能な限り削減する。

本仕様書は、現行データを維持しながら、

> 商品マスター → 登録対象商品を選択 → 楽天用データ生成 → AIによる文章等の作成 → 確認 → 楽天CSV出力 → FTPアップロード

という流れを構築するための初期仕様である。

**重要：SKU体系そのものはAIに新規設計させず、現在運用している商品コード・代表商品コード・SKUのルールを維持する。**

# 3. 現状の問題点

## 3.1 SKU数が多い

1商品ページ内で、

- 機種
- カラー
- 追加オプション
- セット内容

などの軸が掛け合わされるため、SKU数が大きくなる。

今回の実データでは288 SKUが存在している。

楽天CSVでは例えば、

- `Key0` = 機種
- `Key1` = カラー
- `Key2` = 追加オプション
- `Key3` = お得なセット

という4軸構成が確認できる。

## 3.2 同じ情報を大量にコピーする必要がある

商品単位で共通する情報と、SKUごとに異なる情報が混在しているため、RMSへの手入力・コピー＆ペーストが発生している。

## 3.3 商品マスターと楽天CSVの構造が違う

商品マスターは45列程度なのに対し、楽天CSVは561列ある。

したがって、商品マスターをそのまま楽天CSVにするのではなく、

**商品マスター → 楽天登録用中間データ → 楽天CSV**

という変換層を設けるのが望ましい。

## シート2：楽天登録対象

今回楽天へ登録・更新する商品だけを指定するシート。

例：

| 項目 | 内容 |

| 登録対象 | TRUE/FALSE |

| CSV出力 | 未出力/出力済 |
| 最終確認 | OK/NG |

これにより、1年間分蓄積された商品マスター全体から、今回登録したい商品だけを切り出せるようにする。

# 6. SKU処理仕様

## 6.1 基本方針

SKUはAIに作らせない。

既存の商品マスターにある、

- 商品コード
- 代表商品コード
- カラーコード
- サイズコード
- ベース商品
- その他既存コード

を利用する。

## 6.2 楽天SKUとの対応

今回のデータでは、商品マスターの`商品コード`と楽天CSVの`システム連携用SKU番号`が対応している。

また、楽天CSVの`SKU管理番号`は、既存商品コードをベースにした別ルールで構成されていることが確認できる。

このため、開発時には、

**現在使用しているSKU生成ルールをそのままプログラム化する。**

「似たような文字列だから生成する」のではなく、実際の既存データを基準にルールを確定すること。

# 8. AIの役割

AIには「CSV全体を自由に編集させる」のではなく、**必要な入力情報から指定された項目だけを生成させる**。

例えば、

```text
商品情報
商品名：
機種：
カラー：
特徴：
素材：
対応機種：
付属品：
オプション：
価格：
商品タグ：
```

をAIへ渡し、

```text
商品名
キャッチコピー
PC用商品説明文
スマートフォン用商品説明文
検索キーワード
画像ALT
```

を返す方式を基本とする。

## ChatGPT

仕様設計、データ構造の整理、プロンプト設計、CSV処理ロジックの検討などに利用する。

## Claude

実装方法の検討、GAS・スプレッドシート処理、コードレビュー等について別途検証する。

**「文章生成・判断補助」**

**「SKU・価格・在庫・CSVフォーマットの正確な変換」**

# 11. MCPについて

MCPは今回のシステムでは**必須ではない**。

まずは、

```text
Googleスプレッドシート
↓
GAS
↓
AI API
↓
楽天CSV
```

で十分実現可能かを検証する。

MCPは将来的に、

- AIから外部システムを操作する
- AIからデータを取得する
- 複数サービスを横断して処理する

必要性が出た場合に検討する。

**最初からMCPを導入することを前提にしない。**

---

# 12. エラーチェック

CSV生成時には最低限、以下を自動チェックする。

- SKU重複
- 商品コード重複
- 必須項目の空欄
- 価格の空欄
- 在庫数の不正値
- バリエーション軸の不整合
- バリエーション選択肢の不整合
- 商品管理番号の不整合
- SKU管理番号とシステム連携用SKU番号の不整合
- 文字数制限
- 禁止文字・特殊文字
- AI生成文の未確認
- 商品画像パスの欠落
- 楽天CSV列数の不一致

エラーがある場合はCSV出力を止める。

---

# 13. AI生成文の安全策

AIが作成した文章は、そのまま楽天へアップロードしない。

ステータスを、

```text
未生成
↓
AI生成済
↓
人間確認済
↓
CSV出力可能
```

とする。

特に、

- 対応機種
- 商品仕様
- サイズ
- 素材
- 価格
- セット内容
- 付属品

などの事実情報については、AIが勝手に追加・変更しないようにする。

# 14. 目標とする操作イメージ

最終的には、担当者が、

1. 商品マスターに新商品を登録
2. 「楽天登録対象」をON

7. エラーチェック
8. CSV完成
9. FTPで楽天へアップロード

という流れで運用できる状態を目指す。
